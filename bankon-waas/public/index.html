      What are Ordinals — inscriptions, runes, rare sats?
      
Ordinal theory numbers every satoshi by the order it was mined, so an
        individual sat can be tracked, collected, and inscribed with content carried in a taproot
        witness — an immutable on-chain artifact; runes are fungible tokens etched/minted with the
        same tooling. Custody differs from the wallets above: ordinal wallets are descriptor
        wallets inside your own Bitcoin Core (the node holds those keys), and BANKON keeps
        ordinal and cardinal (plain-BTC) wallets strictly separated so an inscribed sat is
        never spent away as change. Every action is gated fail-closed — dry-run first, explicit
        ⚠ broadcast, refused over 0.1 ₿TC or on unknown balance. Use the 🜚 Ordinals tab above, the
        Console's 🜚 tab, or the Qt app's 🜚 tab — one gated engine behind all three.
        Ordinals guide ↗

        What SegWit actually is BIP141 · BIP143
        

          
Segregated Witness (activated August 2017) restructures how a Bitcoin transaction
          carries its signatures. Pre-SegWit, the unlocking data (signature + public key, the
          scriptSig) sat inside each input, so it was hashed into the txid. SegWit moves that
          data into a separate witness section that is committed to by a new wtxid merkle root
          (stored in the coinbase), while the txid is computed over the transaction without witnesses.

          
    
            
  • Fixes transaction malleability — a third party can no longer mutate a signature
              encoding to change your txid before confirmation. Unconfirmed txid chains (and protocols
              built on them, like Lightning) become safe.
    • 
            
  • Weight units & the witness discount — blocks are limited to 4,000,000
              weight units. Non-witness bytes cost 4 WU each; witness bytes cost 1 WU. Fee rates are
              quoted per vbyte (= weight ÷ 4), so signature data is effectively 75% cheaper. That is
              the entire reason SegWit inputs cost less to spend.
    • 
            
  • BIP143 signature hashing — SegWit inputs sign a digest that commits to the input's
              amount and uses linear-time hashing. This kills the O(n²) sighash DoS and lets hardware
              wallets sign without streaming every previous transaction.
    • 
            
  • Script versioning — the output format (witness version + program) made future
              upgrades soft-fork-clean: version 0 = P2WPKH/P2WSH, version 1 = Taproot.
    • 
          

        

      


      

        Native SegWit — P2WPKH bc1q… · BIP84 · default
        

          lowest feesBTC Standard defaultbech32
          
Pay-to-Witness-Public-Key-Hash. The output script is just
          OP_0 <20-byte HASH160(pubkey)>; the signature and public key go in the witness,
          where every byte gets the 4× discount. A typical input weighs ≈68 vB vs ≈148 vB for
          legacy — roughly 54% cheaper to spend.

          
    
            
  • Address encoding: bech32 (BIP173) — lowercase, case-insensitive, with a BCH checksum
              that guarantees detection of up to 4 character errors and even locates typos. QR codes
              encode smaller in alphanumeric mode.
    • 
            
  • Derivation: BIP84 — m/84'/0'/0' from your BIP39 phrase;
              descriptor wpkh(…).
    • 
            
  • Compatibility: spendable by all nodes; virtually every exchange and wallet can send
              to bc1q addresses today.
    • 
          

        

      


      

        Taproot — P2TR bc1p… · BIP86 · newest
        

          best privacySchnorrrare legacy senders can't pay it
          
Pay-to-Taproot (BIPs 340/341/342, activated November 2021) is witness version 1:
          OP_1 <32-byte x-only pubkey>. The key it exposes is a tweaked key that can
          commit to a hidden tree of alternative spending scripts (MAST).

          
    
            
  • Schnorr signatures (BIP340) — 64-byte, provably non-malleable, and linear:
              multiple signers can aggregate into one signature (MuSig2), so a multisig spend can look
              identical on-chain to a single-sig spend.
    • 
            
  • Key-path vs script-path — the everyday spend is just one signature
              (≈57.5 vB per input, the cheapest spend in Bitcoin). Only if you use a fallback
              script does that branch get revealed — unused conditions stay secret forever.
    • 
            
  • Privacy — every key-path spend looks the same, whether it hides a 2-of-3, a
              timelock, or nothing.
    • 
            
  • Encoding / derivation: bech32m (BIP350, fixes a bech32 checksum weakness for v1+);
              BIP86 — m/86'/0'/0'; descriptor tr(…).
    • 
            
  • Caveat: a handful of very old exchange withdrawal systems still can't send to
              bc1p…; anything maintained can.
    • 
          

        

      


      

        Legacy — P2PKH 1… · BIP44 · compat only
        

          highest feesworks with anything since 2009
          
Pay-to-Public-Key-Hash — the original address format. Output script
          OP_DUP OP_HASH160 <pubkey-hash> OP_EQUALVERIFY OP_CHECKSIG; the signature and
          pubkey travel in the scriptSig at full 4 WU/byte, so an input weighs ≈148 vB.

          
    
            
  • Encoding: Base58Check — mixed case, no error-location, checksum only detects.
    • 
            
  • No malleability fix, no amount commitment in the classic sighash — the problems
              SegWit was built to solve.
    • 
            
  • Derivation: BIP44 — m/44'/0'/0'; descriptor pkh(…).
    • 
            
  • Choose it only when a counterparty literally cannot send to bech32.
    • 
          

        

      


      

        Nested SegWit — P2SH-P2WPKH 3… · BIP49 · transitional
        

          not minted by BANKON
          
The 2017-era bridge format: a P2WPKH program wrapped inside Pay-to-Script-Hash so old
          wallets could send to SegWit users via a familiar 3… address. Inputs weigh
          ≈91 vB — cheaper than legacy, dearer than native. Derivation BIP49
          (m/49'/0'/0'), descriptor sh(wpkh(…)). Now that bc1q is universally
          supported the wrapper is pure overhead, so BANKON doesn't create these — but it can watch and
          spend them if you import one.

        

      


      

        Multisig — P2WSH bc1q… (62 chars) · N-of-M
        

          no single point of failurewsh(sortedmulti)
          
Pay-to-Witness-Script-Hash — witness v0 with a 32-byte SHA256 of the full
          spending script (vs 20 bytes for P2WPKH, hence the longer address). BANKON registers
          wsh(sortedmulti(N, xpub…)) descriptors: N of M cosigners must sign, and
          sortedmulti orders keys deterministically so every cosigner derives identical
          addresses.

          
    
            
  • Cosigners share only public data — { xpub, fingerprint, path } at
              m/48'/0'/0'/2' (BIP48). No seed ever leaves a device.
    • 
            
  • Spending flow: the node builds a PSBT (BIP174) → each required cosigner signs
              offline → combinepsbt merges the partials → broadcast. Verified end-to-end
              2-of-3 on regtest.
    • 
            
  • Cost: the witness reveals the full script + N signatures, so inputs are heavier
              than single-sig (a 2-of-3 input ≈105 vB) — still far cheaper than legacy multisig, thanks
              to the witness discount.
    •
